Read AGENTS.md first and follow it strictly. Do only what is on this page.
No UI, no screens, no components. This prompt defines types and keys; it does not
provide content.

1. Derive every row type from the generated `types/database.ts` using Supabase's
   helper types (https://supabase.com/docs/reference/javascript/typescript-support).
   Put the aliases in `types/catalog.ts`: `BookCatalogRow` from `books_catalog`,
   `ChapterCatalogRow` from `chapters_catalog`. Never hand-edit
   `types/database.ts` — it is regenerated by `npm run types:gen`. If a view is
   absent from the generated file, STOP and report which one rather than declaring
   the shape by hand.
2. Encode the nullable columns in the types and in a comment, because AGENTS.md
   makes each a real UI state, not an edge case:
   `audio_duration_seconds` / `total_duration_seconds` null means duration UNKNOWN
   and must never render as `00:00`; `cover_path` null is valid and resolves to the
   local `cover-placeholder.png` from `constants/images.ts`. Add
   `formatDuration(seconds: number | null): string` in `lib/format.ts` returning a
   "duration unknown" string for null, and make it the only place duration is
   formatted.
3. Map the `maturity` enum to display labels in `lib/labels.ts`. The enum value
   `mature_17` displays as "Mature 18+" — the value and the label differ by
   design; do not rename the enum and do not display the raw value anywhere.
4. Reader-facing reads go only to `books_catalog` and `chapters_catalog`, which run
   `security_invoker=on`. Querying `books` or `chapters` directly is forbidden: the
   views pre-compute `chapter_count`, `audio_count`, `free_chapter_count` and
   `total_duration_seconds`, and going around them reintroduces the N+1 the views
   exist to kill. `chapters_list` and `chapters_needing_attention` are admin-only —
   do not reference them.
5. Create `data/genres.ts` as the single source for genre chips, typed as a
   readonly tuple with a derived union type. AGENTS.md lists seven:
   Romance, Werewolf, Vampire, Fantasy, Possessive, Billionaire, Dark. Each entry
   carries the exact string used in the `genres` text[] column plus its display
   label. Note in a comment that M3's tab strip surfaces only six of these and
   that the mismatch is an open question, not a bug to fix here.
6. Create `data/seed-catalog.ts` typed as `BookCatalogRow[]` / `ChapterCatalogRow[]`
   for local UI work only. Mark it at the top: not the system of record, never
   imported by a screen after that screen is wired to the database, and it must
   not be written back. You may not INSERT, UPDATE or seed anything into `books`
   or `chapters` — if real data is too thin to build a screen against, that is a
   blocker to report, not to fill in.
7. Declare all TanStack query keys in one file, `lib/query-keys.ts`, as a key
   factory (https://tanstack.com/query/latest/docs/framework/react/guides/query-keys),
   hierarchical so a prefix invalidates its children. Cover at least: catalog
   lists by genre, book detail by id, chapter list by book id, chapter text by
   chapter id, search by term, reading position by chapter id, unlocks by user,
   library items by user. Every user-scoped key must include the Clerk user id as
   a segment so the persisted cache cannot leak across accounts.
8. Co-locate fetchers with keys using the `queryOptions` helper
   (https://tanstack.com/query/latest/docs/framework/react/guides/query-options)
   in `lib/queries/`. Fetch `script_text` in its own query, keyed per chapter,
   never as part of a list query — chapter text is large and serials run 85–200
   chapters. Note that `script_text` is expected to contain exactly three Markdown
   marks and nothing else; the reader in prompt 16 relies on that.
9. Define the asset-state discriminated union in `types/states.ts`:
   `locked | unlocked | downloaded | reading`, mutually exclusive, plus a pure
   `resolveChapterState()` that takes the chapter's `access` value, the
   `free_chapters_at_start` setting, and optional per-user inputs. Chapter access
   in the database is only `free | locked`; the four states are computed per user.
   Read `free_chapters_at_start` from live `app_settings` — do not hardcode 3, and
   do not trust the migration default, since the live value governs.
10. Add placeholder types for the Phase 2 tables that DO NOT EXIST yet —
    `reading_positions`, `unlocks`, `library_items` — in `types/unbacked.ts`, each
    with a loud `// UNBACKED: no table until prompt 14` header, declared by hand
    only because there is nothing to generate from. Any hook consuming them must be
    obviously stubbed. Do not create a migration here; prompt 14 owns that.
11. Mirror TanStack/Zustand ownership in the file layout: `lib/queries/` holds
    server state only. Do not create a store, a slice or any transient state here —
    prompt 08 owns Zustand.

Do not: write a migration, a view, an RLS policy or any SQL; call
`supabase.from(...).insert/update/delete` anywhere in this prompt; invent a
`trending` metric — there are no view counts and no reads table, so leave the
trending key defined with a `// NO BACKING METRIC` comment and no fetcher; import
anything from `data/seed-catalog.ts` outside a screen's mock path; use `any`, a
non-null assertion on a nullable column, or a type assertion to paper over a
missing view; touch `tailwind.config.js`, `global.css` or `types/database.ts`.

Finish by running `npx tsc --noEmit`, then paste the derived aliases from step 1,
